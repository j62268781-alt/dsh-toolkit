# Git 约定

把三项 Git 约定写进系统提示词，并提供一个设置面板：**设置 → Git**。

包名：`dsh-toolkit-git`。可由 dsh-toolkit 聚合安装，也可单独作为 DSH bundle 安装。

DSH 自己没有 Git 界面，真正敲 `git` 的是模型自己。所以这个模块不接管你的仓库，而是把设置
变成三层：**内置工具**（参数由宿主拼，模型只负责调用）、**一道 shell 守卫**（挡住裸 `git push --force`）、
以及**一段系统提示词**（把工具说不清的习惯告诉模型）。

## 三个设置

| 设置 | 默认 | 生效方式 |
| --- | --- | --- |
| 分支前缀 | 空 | 新建分支时把 `<前缀><描述>` 作为分支名 |
| 始终强制推送 | 关 | 推送时用 `--force-with-lease`，而不是裸 `git push` |
| 提交说明指令 | 空 | 附加到「写提交说明」这件事的指令里（例如 Conventional Commits + 中文） |

三项全空时模块注册的提示词段也是空的，对模型没有任何影响。

- **分支前缀**只允许字母、数字、`.`、`_`、`-`、`/`；不能以 `-` 或 `/` 开头，不能含 `..`，
  不能有连续的 `/`，最长 100 个字符。带非法字符时面板会就地提示并拒绝保存（与 Qoder 一致）。
- **始终强制推送**是「推送当前分支」这一动作的策略：`--force-with-lease` 会在远端已经变了的时候拒绝覆盖，
  比 `--force` 安全；模块的提示词里明确禁止裸 `--force`。
- **提交说明指令**是自由文本，最长 4000 个字符，去首尾空白后保存；停手 1.2 秒自动保存，失焦立即保存。

## 六个内置工具

参数由宿主拼，模型只负责调用——这样「始终强制推送」与「分支前缀」在**每一次**操作里都生效，
不依赖模型有没有读到提示词。

| 工具 | 做什么 | 调用前先检查什么 |
| --- | --- | --- |
| `git_push` | 推到 `origin`，按设置加 `--force-with-lease`，缺上游时补 `-u` | 有没有 `origin`、是不是游离 HEAD、上游比本地多几个提交（落后且没开强推就直接拦下） |
| `git_branch_create` | 建分支并切过去，自动拼前缀，重名退到 `-2`、`-3` | 仓库是否可用、名字是否合法（本地正则先挡，最终由 `git check-ref-format` 裁决） |
| `git_commit` | `git commit -m`，可只提交指定路径或先 `add -A` | 暂存区是不是空的（不让「以为改过」变成空提交） |
| `git_sync` | `fetch --prune` 或 `pull`（默认 `--rebase`） | 游离 HEAD、未提交改动、有没有上游 |
| `git_branch_delete` | 删本地分支，默认只删已合并的 | 是不是当前分支、有没有未合并的提交（要删得显式 `force: true`） |
| `git_branch_rename` | `git branch -m`，省略 `from` 就改当前分支 | 目标名是否已存在、新名字是否合法 |

工具失败时给的是**下一步**而不是 git 原文：没有 `origin` 就说先 `git remote add`，工作区脏就说先
提交或 `git stash`，冲突就说解决后 `git rebase --continue`。

## 输入框里的分支按钮

除提示词外，这个模块还在会话输入框左侧放了一个显示当前分支的按钮（`conversation.input.left`）：

- 点开是一个带搜索框的弹层，列出当前目录的本地分支（按最近提交排序，当前分支置顶并打勾）；
- 点一项就切过去（`git switch`，老版本 git 退回 `git checkout`），工作区有未提交改动时先弹确认；
- 底部「新建分支」用**分支前缀**预填输入框，校验通过后 `git switch --create` 并切过去；
- 目录不是 Git 仓库或本机没有 `git` 时按钮自动隐藏／显示原因，不留一个点不动的空壳。

它走三条 host 路由：`/api/plugins/toolkit/git/branches`、`/checkout`、`/create-branch`（`src/modules/git/host/routes/branches.ts`）。
路由是可选的：没有 Web 服务（终端里跑 agent）时，提示词照旧生效。

## 为什么主要是工具而不是钩子

DSH 的 bash 工具可以执行任意命令，没有「提交」这种可拦截的高层操作；在 shell 层拦截 `git commit`
要么漏（`git -c … commit`、脚本里的 commit），要么误伤（`git commit --dry-run`）。
所以真正的落地是内置工具：模型调用它们，参数就在宿主手里。提示词是**兜底**——工具没被调用时
（比如模型自己在 shell 里敲），约定仍然写着。守卫只挡一件事：开关打开时的裸 `git push --force` / `-f`。

## 面板能看到什么

- 分支前缀：输入框，失焦或回车保存，非法值就地报错；
- 始终强制推送：开关，切换即保存，失败则回滚；
- 提交说明指令：六行文本框，带字数计数与「正在保存…／已保存。」状态；
- 配置文档不可写时（例如只读来源）整页变只读并给出说明。

## 已知限制

- 约定只对「模型自己执行的 Git 操作」有效。你在终端里手敲的命令不受影响。
- 提示词是每轮会话开始时组装的；改完设置后新开一轮对话即可生效，不需要重启 DSH。

源码集中在仓库的 src/modules/git；请在仓库根目录运行 pnpm build，不要编辑本包的 lib 构建产物。
