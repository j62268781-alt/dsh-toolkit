# 桌面宠物与灵动岛

`dsh-toolkit-pet` 提供桌面悬浮宠物和屏幕顶部灵动岛。两种窗口共用所选形象，可以分别开启；初始均关闭。配置通过 DSH 设置表单保存，运行中的窗口接收实时更新。

## 使用

构建并加载插件后，打开「设置 → 桌面宠物」，选择形象，再开启悬浮宠物或灵动岛。首次使用会下载并准备 Electron 运行时，也可以先点击「准备桌面运行时」；桌面运行时那一行会显示下载进度（百分比与已下载/总大小），准备完成或失败后进度条消失。准备或启动失败时，设置页会显示原因并提供重试。桌宠由插件管理，无需手动启动另一款桌宠软件。

桌面悬浮支持拖动位置、调整宠物大小和会话气泡宽度。灵动岛支持独立调整收起尺寸、空闲时保留显示，以及在其他显示器上同步显示。各屏幕共享会话内容，鼠标悬停、展开和收起只作用于当前窗口。按住胶囊拖动可以移动窗口：桌宠能拖到任意屏幕，灵动岛只在它自己的屏幕内移动，位置按显示器记住（写在 `~/.dsh/toolkit/pet/layout.json`，重启后仍在原处），拖动超过 4px 不会触发点击。收起态左侧是所选形象，右侧是一枚状态徽标：`正在工作`（绿，转圈；有排队输入时缀 `·N`）、`等你批准`（橙，`!`）、`等你回答`（青，`?`）、`目标已暂停` / `目标被卡住`（琥珀 / 珊瑚，`!`）、`轮次已用尽`（琥珀，`!`）、`有输入待发`（紫，`→`）、`有新结果`（蓝，`✓`）、`失败`（红，`×`）、`已停止`（灰蓝，`–`，用户按了停止）、`可继续`（青绿，`↺`，上一回合失败且可空提示重跑），宿主没给出等待原因时退回通用文案 `需要你处理`；有排队输入时缀 `·N`，多个会话时徽标补 `+N`（完整数量仍在悬停提示里）；没有会话活动时显示 `hi~` 问候，此时悬停不会自动展开。徽标文案决定胶囊宽度（收起态在 212–280px / 有刘海屏 360px 区间内自适应），仍受「灵动岛宽度」百分比约束。

展开态按 Qoder 的内容模型分两种互斥形态。排在首位的会话正在执行、且整份列表没有待处理事项时，显示「运行中列表」：最多三行，每行是两行文字（标题、`状态短语 · 摘要`），两行都单行省略，没有头像、没有按钮、没有输入框，也不出现滚动条。运行中列表每行的状态短语后面还跟着进度（`第 2 轮 · 2 个子代理`）；单会话详情的进度行更完整（`第 2 轮 · 第 3 步 · 正在用 bash · 输出 3.4K`），有什么说什么、没有就不占位。其余情况显示「单会话详情」：标题与状态短语（`正在执行` / `等待你的处理` 及其原因 `等你批准` `等你回答` `目标已暂停` `目标被卡住` `轮次已用尽` `有输入待发` / `本轮已停止` / `本轮已完成` / `本轮执行失败`）加右侧相对时间（`刚刚` / `5 分钟前`）、最多三行的说明；有待办时在说明下方内联待办块（审批为橙色、提问为青色，带命令或问题原文）。两种形态都不是「先用鼠标选中、再点按钮」，而是整行 / 整张卡片本身就有 hover 高亮，鼠标移上去直接点一下就能打开对应会话，打开成功后灵动岛随即收起。点开即视为「已读」：该会话立刻从实时活动里消失、徽标随之回落，直到它再次产生新动作；已读记录写在 `~/.dsh/toolkit/pet/seen.json`，重启后不会重复提醒。从别处进入同一个会话同样算已读：系统通知点击跳转、或在应用里切到目标会话时，客户端半部读既有会话列表快照里的 `retainedBy.mainView`，一发现主视图换了会话就向 host 上报一次 `seen`（同一个会话重复渲染只报一次），灵动岛状态随即刷新。从别的应用切回 DSH 也算「看过了」：客户端只在窗口真的在前台（`visibilityState === 'visible'` 且窗口有焦点）时才上报，一次激活会把岛上针对当前会话的「有新结果」一并清掉；窗口失焦或隐藏期间不报，提醒照常保留。实时活动本身也只保留近期内容——结束或暂停的会话留 30 分钟、判定为正在执行的留 6 小时（防止崩溃残留的 `running` 占位），等人的审批与提问不受时间限制。

形象除了内置的 DeepSeek酱，还可以直接从 Petdex 社区安装，不需要另装 CLI 或桌宠软件。设置页「宠物形象」组右侧的「浏览宠物库」打开独立弹窗：弹窗不铺满窗口，四周留白、居中显示，默认 920×640，最小 640×420、最大 1120×860，并随窗口尺寸向下夹取（窗口再小也不会溢出）；右下角把手可拖拽改宽高，聚焦把手后方向键按 16px 步进（Shift 加速到 64px），松手后尺寸记在本机，下次打开沿用。弹窗右上角是宿主的关闭图标，点它、按 Esc 或点弹窗外面都能关；搜索行固定在标题下方的工具条里，列表怎么滚都不跟着动，搜索按钮右边是「全部 / 已安装 / 未安装」三段筛选（默认全部，切换后重新拉取）；宫格每行 6 只、一次拉 60 只，滚到底自动续拉下一批（页面里只有已经滚过的那些，目录 5000+ 条也不会一次搬进来）；卡片自上而下是宠物样子、名称（单行省略）、副标题即宠物 ID（固定单行，超出省略）；预览图用 `loading="lazy"`，没滚到视口的卡片不下载，卡片本身也带 `content-visibility: auto`，滚动时只排可见的那几行，内存与重排都跟着结果条数线性压住，卡片底部是一条整宽的「安装」或「卸载」按钮条（平时淡色描边，悬停卡片时安装条点亮成主色、卸载条转成 DSH 的删除红与危险底色），安装过程中这条按钮会变成进度条、中间显示 Host 推来的下载百分比（按 Content-Length 计算，安装结束自动消失），鼠标移上去卡片会轻微抬升高亮、预览图略微放大；弹窗底部只留一行「已显示 N / 共 M」，没有分页条；安装时 Host 会从 Petdex 的公开清单取得 `pet.json` 与精灵表，校验目录与尺寸（8 列 × 9 行或 11 行、每格 192×208、单文件不超过 8MB）后原子落盘到 `~/.dsh/toolkit/pet/pets/<slug>/`；装好的宠物直接出现在「当前形象」下拉里（内置与已安装混排，不分组），可随时「卸载」。安装失败或本地包损坏不会影响其他宠物。卡片上的样子由插件的受认证路由 `/api/plugins/toolkit/pet/asset?slug=<slug>` 提供，Host 取 Petdex 的预览条（idle 前 6 帧，约 40KB）后缓存到 `~/.dsh/toolkit/pet/cache/previews/`，离线时用缓存。所有下载只允许 https、只解析固定根目录下的文件，不走用户提供的任意路径。

待审批或待回答时，整张卡片同样只负责打开原会话处理：宿主当前没有公开的批准 / 回答接口，灵动岛不会代你 approve 或 deny，审批仍由会话里的 answerer 决定。胶囊在收起态点击或悬停 300ms 展开；鼠标移出窗口会立即收起，窗口失焦时同样收起；展开时胶囊本身不再响应点击，避免挡住内容。桌宠气泡保留原来的卡片列表，卡片下方仍可直接输入补充要求，输入时保持展开。

macOS 上，有刘海的屏幕通过 `NSScreen.safeAreaInsets` 和刘海两侧的可用区域取得真实几何位置，黑色窗口贴住屏幕顶边，收起高度与系统刘海安全区一致（如 32pt），不随高度滑块放大；悬停预展开只增加宽度，不向下侵入应用标题栏。状态位于刘海两侧，展开内容放在刘海下方。展开面板按 Qoder 的面板尺寸展开（刘海屏 590px、普通屏 552px，屏幕更窄时按屏宽留 120px 封顶），收起态那点宽度装不下内容，也装不下与摄像头区并排的徽标。可见的黑色面板在刘海模式下收起态左右各内缩 6px、展开态内缩 19px 肩部，因此胶囊里的形象与徽标跟着让位（收起 `padding-inline:18px`、展开 31px），距可见边缘分别回到 12px 与 16px；展开内容的左右内边距相应改为 39px（肩宽 19 + 20），行与卡片再各自外扩 8px 作为 hover 高亮，因此文字距可见边缘 20px、高亮块 12px，不再贴边。摄像头所在的实体区域没有可绘制像素，窗口只能围绕它与黑色背景连成一体。没有刘海的屏幕顶部是菜单栏，胶囊挂在菜单栏下方（`workArea.y` 再留 6px），不会压住状态栏图标；系统几何数据不可用时也使用这一布局。此窗口由工具箱创建，不会接管 Apple 的实时活动或系统菜单栏控件。

## 配置

聚合工具箱和独立包都使用相同的模块配置字段，安装为聚合包不会改变已有宠物设置。更早的兼容入口曾将这些字段放在 `pet` 命名空间中。

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `activePet` | `aoi-shark-maid` | 两种窗口共用的形象 ID |
| `petEnabled` | `false` | 显示桌面悬浮宠物 |
| `petSize` | `100` | 宠物大小百分比，50–100 |
| `bubbleWidth` | `280` | 会话气泡宽度，240–480 像素 |
| `islandEnabled` | `false` | 显示屏幕顶部灵动岛 |
| `islandIdle` | `true` | 空闲时保留灵动岛 |
| `islandAllDisplays` | `true` | 在其他显示器上同步显示 |
| `islandWidth` | `100` | 灵动岛收起宽度百分比，75–150 |
| `islandHeight` | `100` | 普通屏幕的灵动岛收起高度百分比，75–150；刘海屏固定贴合系统安全区 |
| `electronPath` | 空字符串 | 指定现有 Electron 可执行文件的绝对路径 |

`DSH_TOOLKIT_ELECTRON_PATH` 也可指定可执行文件。运行时未指定时，插件使用 Electron 43.3.0，按平台与架构缓存在 DSH 数据目录下的 `toolkit/pet/electron` 中。Electron 只发布整包（43.3.0 的 Windows x64 压缩包约 138MB），没有官方精简版；插件在解压后删掉界面语言包与随包发的 Chromium 许可证文本（19MB）：Windows / Linux 删 `locales/` 下除 `en-US.pak` 之外的 .pak，macOS 删 `Electron Framework.framework` 里除 `en.lproj` 之外的 .lproj（解压 295MB → 229MB）。helper 没有菜单和对话框，缺对应语言时 Chromium 回落到英文；`resources.pak`、`icudtl.dat`、`Electron.app/Contents/Resources/default_app.asar` 不能删，实测删了 Electron 直接退出，并用 `cacheMode: Bypass` 自己管临时压缩包、解压完立即删除，不再把整包多留一份在 `%LOCALAPPDATA%\electron\Cache`。下载走插件的自定义 downloader，按 Content-Length 汇报百分比；判死条件是「60 秒没有新字节」而不是总时长，慢链路也能下完。默认从 GitHub Release 取包，国内直连通常只有几十 KB/s，可先设 `ELECTRON_MIRROR`（例如 `https://npmmirror.com/mirrors/electron/`）再点「准备桌面运行时」——镜像地址由 `@electron/get` 解析后交给同一个 downloader，进度与校验和都会照常工作。Host 启动辅助进程前会清除 `ELECTRON_RUN_AS_NODE`，确保 Electron 创建图形窗口。

## 运行方式

Host 模块订阅会话状态，汇总活动并向设置页和辅助进程推送更新。设置页使用 DSH 鉴权路由；辅助进程通过独立的回环地址和随机令牌连接，使用自身的 Electron 主进程创建透明、无边框、置顶窗口。辅助进程随插件退出，并监测 Host 生命周期。

此实现不依赖 DSH 私有 Electron IPC 或修改 DSH 安装文件。Host 必须运行在有桌面会话的本机；远程或无图形环境的 Host 无法将这些窗口显示到浏览器所在的电脑。点击返回工作台需要有连接着的 DSH 页面接收导航事件。

## 资源与范围

内置一套 `aoi-shark-maid` 资源（Petdex 社区的「DeepSeek酱」形象，1536×2288 的 8 列 × 11 行 v2 精灵表，每格 192×208，直接从上游包取得、未做改动；授权情况见 `src/modules/pet/host/runtime/pets/NOTICE.md`）。原先由仓库里的程序画笔绘制的 `deepseek-whale` 已按用户要求移除，`PET_IDS` 里只剩这一个内置形象。

宠物动作按 Qoder 的语义组织：灵动岛收起态按会话状态循环播放动画（运行中游动、普通等待、审批、提问、失败、有新结果 `review`、空闲各有对应姿态），展开态与其它交互不额外播动作。宠物包在 `pet.json` 的 `animations` 里按动作名登记片段（如 `"idle": "motion/idle.webp"`）后，渲染端直接播放这段 60 fps 动画 WebP —— 与 Qoder 内置宠物一致；没有登记片段的宠物（现在内置的 DeepSeek酱 与第三方 Petdex 宠物都是这种）以及 `prefers-reduced-motion` 场景回退到精灵表逐帧绘制（帧时长更稀疏，约 5 fps）；精灵表的慢动作行（`idle`、`waiting`、`review`）在这条回退路径上做相邻帧交叉淡化——桌宠按 60 fps、灵动岛按 30 fps 重绘，帧长不变、帧之间用 smoothstep 插值，实测逐帧像素变化峰值从 6.99 降到 3.22、p90 从 5.51 降到 2.02。跑动 / 跳跃 / 失败行逐帧差异太大（相邻帧平均 RGB 差 37–87），补间会拖出两条腿的重影，所以保持逐帧硬切。16 方向视线帧只有静态帧，始终走精灵表。桌面桌宠在此之上有交互动作——拖拽时朝拖动方向跑、悬停跳一下、启动后 2.6 秒内挥手打招呼；精灵表第 9–10 行的 16 个方向帧让眼睛跟着鼠标转（方向 0 朝上、顺时针每 22.5° 一档），久坐 8 秒后进入慢速 idle，并每隔几秒随机瞟一个方向（`prefers-reduced-motion` 下不做张望，宠物保持静止）。插件代码采用仓库 MIT 许可。未使用 Qoder 官方宠物美术或 `dsh-pet` 的受限素材。

当前版本支持内置形象与 Petdex 在线安装，不含语音输入或触觉反馈。安装的宠物素材由各 Petdex 作者提供，按包清单声明使用。macOS 使用 AppKit 的真实安全区域数据识别刘海；其他平台和无刘海显示器使用独立胶囊布局。平台对窗口置顶、全屏空间和多显示器的处理可能不同，需在对应桌面系统上实测。

外观参考 [Apple Live Activities 设计指南](https://developer.apple.com/design/human-interface-guidelines/live-activities)，刘海定位依据 [NSScreen.safeAreaInsets](https://developer.apple.com/documentation/appkit/nsscreen/safeareainsets) 与两侧可用区域。布局采用纯黑背景、两侧内凹肩部与刘海拼接、右侧文字徽标和下方展开内容，展开态沿用工具箱的两形态会话视图（运行中列表 / 单会话详情 + 待办内联）；徽标、两形态与配色参考 Qoder CN 灵动岛的内容模型。

会话状态采用实时事件和现有投影视图。宿主把审批、提问、目标暂停 / 阻塞、轮次用尽、排队待发都压成同一个 `waiting`，因此插件把这些原因拆成 `waitReason` 单独下发，徽标文案、图标与配色据此区分。「已被打断」不是投影字段：宿主不广播 turn/end，插件在会话状态转为停止时回读该会话日志的尾页，看最近一条 `turn/end` 的 `reason.kind` 是不是 `aborted`；读不到就当作正常结束，不会凭空造出一个「已停止」。进度信息同样靠回读尾页：宿主不广播 `turn/end`，也没有可读的 `sessionStats`，所以插件在会话状态变化和活动事件上读一页该会话日志（默认 40 条，按会话节流到 5 秒一次；热态 1–2ms、冷态约 80ms）。宿主重启后已存在的会话不会补发状态或活动事件，所以除了这两类事件，插件还每 5 秒补扫一遍——只扫全部在跑的会话和最近更新的三条，其余会话读了也没人看，否则它们的进度行会一直是空的，从 `step/start` 取回合号与步骤，从还没有 `tool/result` 的 `tool/call` 取「正在用哪个工具」，从 `turn/end` 取结束原因（`aborted` 即「已停止」）；读一页同时拿这三样，不额外多开一次读。累计输入输出仍走可以读到的那几个投影：`tokenUsage` 给输出 token，「可继续」看 `conversationContinuation` 是否给出失败回合的 seq。带 `wire` 却拿不到的东西也得说清楚：`turnOutline`、`contextBreakdown`、`todos` 虽然在包里声明了 `wire`，但这个宿主没有把它们注册成可读单元，`snapshot()` 永远返回 undefined（`sessionStats`、`contextPressure`、`llmRetry`、`turnBoundary` 更是 Host-only），所以岛上不显示上下文大小、待办原文和 token/秒这类数字。插件加载前已经等待的批准，以及历史失败记录，当前无法完整恢复；新产生的批准和问题会显示为待处理，并引导到原会话操作。宿主没有公开的批准 / 回答接口，批准只能由会话内的 answerer 决定，因此灵动岛与桌宠气泡都只提供「打开会话」入口，不会在岛内直接批准或回答。
