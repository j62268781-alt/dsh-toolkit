# DeepSeek Harness 桌面端开机动画 · 设计方案

> 配套演示：`preview/demo-boot.html`（可直接打开；可切浅色/深色、点击跳过、可重播）
>
> 当前实现是 **A4「自绘」**：鲸鱼先被一笔描线画出来，再填成实心。没有牵引索、没有索扣。
>
> 这份文档回答一个问题：**桌面 App 的开机画面，应该长什么样、为什么**。
> 上一版的「鲸鱼从海里跃出」是一个很好的片头，但它更像**网页的 launch screen**；
> 桌面端要的是**「应用正在打开」**，两者的分寸不一样。

---

## 一、桌面端和网页端，开机画面的要求根本不同

| | 网页 / 整屏接力页 | 桌面 App |
| --- | --- | --- |
| 心理预期 | 加载页可以是一出小电影 | 用户刚点了图标，想看的是「我的东西回来了」 |
| 屏幕归属 | 整屏都是你的 | 只是窗口内容区；标题栏、三灯、Dock 都是系统的 |
| 时长耐心 | 3–6s 可接受 | **1.5–2.5s** 是上限，超过就觉得卡 |
| 性能余量 | 网络还在加载，主线程空闲 | 冷启动时 JS 正在装配插件，**主线程最忙** |
| 主题 | 站点一套皮肤 | 必须跟随 App 的浅/深色，**闪一下白就是 bug** |
| 结束方式 | 整页替换 | 要「让出位置」，不能砸一下消失 |

所以桌面版的设计目标不是「更好看的动画」，而是：**短、轻、不抢戏、和 App 同一套视觉语言**。

---

## 二、三条设计原则

1. **只演「装配完成」这一件事。**
   DSH 开机做的是：读 profile → 装配插件 → 恢复会话。动画只表达「这些东西被成形、就位」，
   不复述具体步骤（写日志式的逐条吐字更像调试输出，会让人以为卡住了）。

2. **用产品的隐喻，但隐喻必须自解释。**
   好隐喻 = 不需要旁白就成立。试过 Harness＝挽具（牵引索 + 索扣），概念很贴产品名，
   但用户第一反应是「这两条线和这个弧度是什么意思」—— 这就是失败信号。
   现在用的是「把这个图形画出来」：描线 → 填色，所有人都懂，而且它同时就是
   "内核在装载、插件在装配"的可视化。

3. **结束时把窗口让出来，而不是消失。**
   收尾是**整体上浮 8px 淡出 300ms**，眼睛看到的是「这一层退场」，
   而不是「有个东西砸下去然后没了」。

## 三、方案 A4（当前实现）：把这个图形画出来

```
 0ms     窗口内容区几乎空白，只有极淡的点阵
 60ms    点阵由中心向外淡入，中心起一层冷光
 260ms   一笔描线开始沿鲸鱼轮廓走（1020ms 画完）
 1120ms  轮廓画完，实心填充从 0 淡入（520ms）
 1260ms  字标 DEEPSEEK HARNESS 浮现：opacity 0→1、字距 .42em → .26em
 1500ms  下方 136px 细线开始呼吸式扫过
 1900ms  ready：整层上浮 8px 淡出 340ms → 露出已经渲染好的 App
```

**为什么换成这个**

上一版是「两束牵引索 + C 形索扣」—— 它是产品名 Harness（挽具）的字面隐喻，
但图形本身必须配解释才成立。这一版把"落定"换成了**所有人默认理解的**
一句话描述：

> 这个图形正在被画出来。

它同时是三件好事：

1. **不需要旁白**。描线→填色是绘图软件、签名、logo 动画里反复用过的语言，
   用户看一眼就知道"正在生成"。
2. **它是开机动作本身**。App 冷启动时内核在装载、插件在装配，
   图形一笔笔成形，正好是这个过程的可见化。
3. **零成本实现**。同一条 path 画两遍：一条 `stroke-dasharray` 描边，
   一条 `fill` 淡入；没有 canvas、没有 rAF、没有额外资源。

**保留不变的部分**（用户认可的三样）：logo 本身、字标、进度线；以及
全程无抖动、`ease-out` 单调收敛、1.9s 内结束、任何输入可跳过。

**中途试过又放弃的**

- **A1「Harness 牵引」**：两束弧线 + C 形索扣扣住鲸鱼。寓意最贴产品名，
  但需要解释，已弃。
- **A2「扫光就位」**：一条扫描线掠过、鲸鱼对焦。干净但丢了产品隐喻，已弃。
- **A3**：A1 的无抖动版（只删回弹/过冲）。仍属"需要解释的图形"，已弃。
- **A4 的落定回弹**：试过填色落定那一刻整组 `scale 1.062 → 1`（480ms，单向无过冲）。
  实测几何是单调收敛的、技术上没问题，但观感上"画完的静态图突然动了一下"像是画面抖。
  结论：**描线结束本身就是到达信号，不需要再补位移**。已删除，现在填色段落完全无位移。

**为什么不做鲸鱼游动 / 粒子 / 波浪**：那些需要 canvas 或大量 rAF，冷启动时
正好和插件装配抢主线程；当前实现是**纯 CSS + 内联 SVG**，零 rAF、零 canvas。

## 四、备选方案（还没做，想换方向可以随时补）

**B.「声呐」** — 深色底，中心发出一圈声呐，鲸鱼以剪影从底部掠过，尾迹划出一条线，
这条线抬起变成字标的基线。感受：安静、有信号感。适合偏「深海」的品牌调性，
但需要 canvas 或较长 SVG 路径动画，桌面冷启动成本比 A 高。

**C.「终端启动序列」** — 等宽字体吐几行 `harness · loading profile desktop… · mounting plugins 12`，
光标块闪烁，最后光标块变成鲸鱼标记。最「开发者」，和 DSH 的定位最贴；
但风险是和真实控制台输出混淆、并且逐字动画在慢机器上会看起来像卡住。

**D.「水面倒影」** — 鲸鱼从顶部入水，水花涟漪扩散成字标基线。v1 的收敛版，适合保留电影感。

**A1/A2/A3**（都做过、都已弃）— 依次是「牵引索+索扣」「扫描线」「牵引索无抖动版」，
弃用原因统一是：图形需要解释才成立。当前的 A4 改走「把图形画出来」这条更普世的路。

> 我的建议：**A 作为默认**（最稳、最贴产品名、开销最低），
> 如果喜欢更有电影感，把 A 的「对焦」换成 D 的「水面」，其余节奏不变，成本很小。

## 五、规格（给实现用）

| 项 | 值 |
| --- | --- |
| 总时长 | 1900ms（`minShowMs` 建议 1200、`maxShowMs` 4000） |
| 可跳过 | 点击 / Esc / Space / Enter，跳过时直接进收尾（300ms） |
| 主题 | 跟随 `document.documentElement` 的 `data-ds-dark-theme`；颜色只取令牌，不写死 |
| 背景 | `--dsh-boot-bg`（ui-theme 的 boot 注入已经设好，浅 #ffffff / 深 #151517） |
| 标记色 | 插件自己的 `--sk-ink`（浅 #0f1115 / 深 #f9fafb），跟着 `body[data-ds-dark-theme]` 切 |
| 强调色 | `--sk-accent`（浅 #4176e6 / 深 #7aaaff），只用在冷光与进度线 |
| 响应式 | 内容居中，标记固定 92px，不随窗口拉伸变形 |
| 减弱动效 | `prefers-reduced-motion: reduce` → 所有动画 1ms，只剩最终画面 + 淡出 |
| 退出 | 整层 opacity→0 + `translateY(-8px)`，300ms，不做缩放 |

## 六、它是怎么接进真插件的（已实现）

gojo 那套是「宿主侧改写 `GET /` 的 HTML」；DSH 里对应的正式接缝是
`webserver/index-inject` 事件 —— 宿主渲染 index.html 前会 emit 一次，订阅者往
table 里 push 行。实现在 `dsh-shell-kit/index.js`：

```js
ctx.on("webserver/index-inject", (table) => {
  table.push(
    { kind: "style", text: css },                              // → <head>
    { kind: "html",  placement: "body", html },                 // → 紧随 <body>
    { kind: "script", placement: "body", text: script },        // → 紧随 <body>
  );
});
```

三段资源分别是 `host/boot.css` / `host/boot.html` / `host/boot.js`，
由 `index.js` 读一次并缓存在模块里。

三个关键点（当时的设计假设都对上了）：

1. **结束条件**：不是 `setTimeout(done, 1900)`，而是轮询「应用外壳是否已经渲染出槽位」
   （`[data-slot="sidebar"]` 或 `[class*="_frame"]`）。实测应用 0.4s 就挂好了，
   所以真正决定时长的是 `MIN_SHOW=1900`。
2. **不要抢失败态**：DSH 自带一张 loading 卡片（`[data-dsh-boot]`），它才是
   "应用挂载完成"的信号。本插件只把它 `opacity:0` 藏起来；若 10s 内应用没起来，
   `bail()` 会把卡片还回去并退出。
3. **主题**：颜色取 `--dsh-boot-bg`（ui-theme 的 boot 注入提供）与
   `body[data-ds-dark-theme]`（同一批注入里设置），所以首帧就是对的，不会闪白。

桌面端与网页端走同一份注入表（桌面壳通过 `dshDesktopBoot.ready()` 取），
所以先在 web profile 验证、再等桌面 App ⌘Q 重启即可。
